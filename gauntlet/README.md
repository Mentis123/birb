# Birb Gauntlet

A Birb Labs racing artefact.

A stylised arcade bird-racing game on a miniature planet. Four birds, three
laps, one glowing ribbon threading ridges and canyons all the way around a
world you can see the curve of.

Birb Gauntlet is an **unlisted Birb Labs artefact**. It ships inside the Birb Mobile
repo and deploys with it, but it lives at its own path and is linked from
nowhere:

> **https://birbmobile.vercel.app/gauntlet**

## Running it

There is no build step. Serve the repo root and open the path:

```bash
python3 -m http.server 8000
# then open http://localhost:8000/gauntlet/
```

Three.js loads from a pinned CDN, so the first load needs network. Everything
else — every mesh, every texture, every sound, even the splash art — is
generated by Birb Gauntlet's own code at runtime.

## What it is built from

Vanilla ES modules and Three.js. No bundler, no framework, no runtime
dependencies (the virtual joystick is Birb Gauntlet's own — nipplejs is not used).

```
gauntlet/
  index.html            shell, entry flow, quality tiers, boot, main loop
  ARCHITECTURE.md       the contract every module is built against — read it first
  src/core/             terrain sampler, cel pipeline, outlines, palette, rng
  src/world/            planet (terrain + instanced props), sky
  src/bird/             procedural chibi bird, its animation rig, flight model
  src/camera/           spring-damped chase camera
  src/race/             course spline + gates, pure race logic, AI racers
  src/fx/               feather particle system, screen shake
  src/ui/               HUD + minimap, procedural key art
  src/audio/            Web Audio synthesis
  src/input/            virtual joystick + keyboard
  dev/                  one isolation probe page per subsystem
```

## Two things worth knowing before you change anything

**Terrain only ever carves downward.** The flight model has no gravity; the
radial clamp in the flight controller is a floor, not a spring. A floor that
could rise above the baseline radius would ratchet a cruising bird upward over
every hill and never let it back down. So `src/core/terrain.js` guarantees
`surfaceHeight <= continentalHeight <= 0`, and everything above the baseline is
expressed with collider-free instanced props. This is the same constraint Birb
Mobile arrived at, and it is load-bearing.

**Stepped lighting amplifies high-frequency normals.** Any surface detail finer
than a few triangles turns into white band noise under a quantised ramp. The
ridge function in `terrain.js` is squared specifically to smooth the normal
crease that was throwing shards across the terrain in the very first captured
frame. Roughness has to read at the scale of a gully, not a pebble.

## Verifying visual work

Every visual claim in this project was checked against a real captured frame.

```bash
node tools/gauntlet-shot.mjs --page gauntlet/index.html --out shots/race.png \
  --query "autostart=1" --w 390 --h 844 --dpr 3
```

The harness serves the repo, drives a headless Chromium, waits for
`window.__GAUNTLET_READY`, and **exits non-zero on any page or console error** — so
a captured PNG is proof the code ran, not proof a file was written.

Useful flags: `--query "autostart=1"` skips the entry pages straight into a
race; `--query "three=local"` loads Three from `node_modules` for environments
with no CDN egress; `--eval` runs an expression against `window.__gauntlet` to
drive the game to a specific moment before capturing.

Isolation probes live in `gauntlet/dev/` — one per subsystem, each rendering that
subsystem alone so a regression can be attributed to a single module.

### Local harness setup

```bash
npm install --no-save playwright three-real@npm:three@0.183.2
git checkout -- node_modules/three/index.js
```

That second line is not optional. This repo **tracks** a hand-written minimal
Three stub at `node_modules/three/index.js` which the Birb Mobile unit tests
import as `'three'`. Any `npm install` prunes it and quietly breaks `npm test`.
The real build is installed under the `three-real` alias for exactly this
reason.

## Relationship to Birb Mobile

Birb Gauntlet is deliberately airtight against its host:

- Nothing in `gauntlet/` imports from the parent `src/`, and nothing outside
  `gauntlet/` imports from inside it.
- The root service worker explicitly bypasses `/gauntlet`. Without that, its
  network-first navigation handler — which caches every navigation response
  under the key `./index.html` — would overwrite Birb Mobile's offline shell
  the first time anyone opened Birb Gauntlet.
- The page is `noindex, nofollow`.

Breaking Birb Mobile from here should not be possible. If you find a way, that
is a bug worth fixing.
